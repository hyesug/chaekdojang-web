# 다층 명반 해석 설계

## 목적

기존 출생 정보 및 명반 계산 결과를 바꾸지 않고, AI 답변이 추상적 운세 문구에 머무르지 않도록 한다. 답변은 계산 사실에서 시작해 핵심 체계의 반복 신호, 현실 사건 후보, 조건부 추론, 시기, 반대 근거를 순서대로 제시한다.

## 범위와 비범위

- 사주, 자미두수, 서양 점성술, 베딕 점성술을 핵심 체계로 쓴다.
- 나머지 열한 체계는 핵심 결론을 보강하거나 불확실성을 설명하는 용도로만 쓴다.
- 출생 시각 보정, 음력 변환, 사주 팔자, 대운, 자미두수, 행성 위치, 다샤 등 기존 계산 함수와 계산식은 변경하지 않는다.
- 특정 회사, 주소, 도시, 실제 사건을 예언하거나 확정하지 않는다.
- API 응답 형식과 기존 일반 운세 화면은 바꾸지 않는다.

## 데이터 흐름

```text
기존 engine / systems / forecast 계산 결과
  -> 새 multilayerInterpretation 레이어
  -> AI context의 "다층 해석 근거" 구획
  -> Claude 시스템 프롬프트의 출력 계약
  -> 기존 스트리밍 UI
```

`multilayerInterpretation`은 계산하지 않는다. 이미 계산된 `readFortune` 및 `forecastPeriod` 결과에서 근거를 추출하고, 체계별 지지 수와 상충 상태를 정리한다.

## 다층 해석 계약

### A. 계산 사실

체계가 반환한 사실과 시기 결과를 그대로 싣는다. 사주 대운·세운, 자미 유년궁, 서양 트랜싯, 베딕 다샤, 각 체계의 headline/facts가 여기에 속한다. 이 구획에는 사건 추측을 넣지 않는다.

### B. 활성 주제

`직업`, `재물`, `관계`, `건강`, `학업`처럼 현재 forecast가 실제로 계산하는 공통 영역을 기준으로 핵심 네 체계의 신호를 집계한다. 세 체계 이상 같은 방향이면 강한 신호, 두 체계면 중간 신호, 한 체계 또는 상충이면 약한 신호다.

### C. 사건 유형

AI는 질문별 사건 후보를 우선순위로 제시한다. 예를 들어 직업 질문은 유지, 자발적 이동, 외부 제안, 역할 변경, 조직 개편, 승진·보상, 부업 병행, 공백을 후보로 삼는다. 후보는 계산 사실이 아니라 해석임을 표시한다.

### D. 원인 추론

보상, 성장, 조직 갈등, 과중 업무, 안정성, 기술 성장, 제안, 통근·가족 같은 현실 원인은 반드시 `해석/추론`으로 분리한다. 사용자가 대화에서 제공한 현재 직장·연봉·거주지 정보도 별도 `사용자 제공 현실 정보`로 분리한다.

### E. 시간과 현실 조건

기존 `forecastPeriod`를 재사용해 향후 연도와 절기 기준 월의 핵심 체계 교집합을 만든다. 연도에서 반기·분기·월로 좁힐 근거가 실제로 겹칠 때만 더 세분화한다. 회사 규모, 조직 유형, 지역, 방향, 정착 가능성은 계산값이 아닌 `구체화 추정`으로 표시하며 근거가 부족하면 명시적으로 유보한다.

## 주·대안·반대 구조

모델은 모든 가능성을 동등하게 나열하지 않는다.

1. 핵심 체계 공통분모를 `주 시나리오`로 둔다.
2. 다음으로 지지되는 방향을 `대안 시나리오`로 둔다.
3. 반대 방향을 지지하거나 시기를 흐리는 체계를 `반대 근거`로 밝힌다.
4. 정밀한 확률 수치는 산출하지 않고, 상대적 강도만 쓴다.

## 문맥 형식

AI 문맥에는 다음 새 구획을 추가한다.

- `다층 해석 근거 / 계산 사실`: 핵심 체계별 사실과 시기 결과
- `다층 해석 근거 / 활성 주제`: 주제별 지지 체계, 상충 체계, 신뢰도
- `다층 해석 근거 / 시기 교집합`: 연도·절기월별 핵심 체계 공통 신호
- `다층 해석 규칙`: 사실, 해석, 현실 정보, 구체화 추정의 표현 규칙

기존 120일 날짜 표와 수술 택일 순위는 유지한다.

## 프롬프트 출력 계약

질문에 직접 답하는 순서는 다음과 같다.

1. 압축 결론
2. 가장 강한 시기
3. 현실에서 가능한 주 시나리오
4. 계산 사실과 체계별 근거
5. 해석/추론 및 구체화 추정
6. 대안 시나리오와 반대 근거
7. 근거 부족 또는 상충 지점

직업 질문은 현재 직업 흐름, 유지·이동 신호, 계기, 준비·실제 이동 시기, 자발성, 조직·직무·경제 조건, 지역, 정착, 반대 시나리오를 검토한다. 단, 데이터가 뒷받침하지 않는 항목은 만들지 않는다.

## 변경 파일

- `public/unse-8f3k2m/src/multilayerInterpretation.js` 신규: 계산 결과를 해석 근거 패킷으로 변환
- `public/unse-8f3k2m/src/aiContext.js`: 새 패킷을 AI 문맥에 삽입
- `app/fortune-ai/route.ts`: 다층 해석 출력 계약과 사실·추론 분리 규칙 추가
- `tests/unse/multilayer-interpretation.test.mjs` 신규: 신호 강도, 상충, 핵심/보조 우선순위, 시기 유보를 테스트

필요 시 `forecast.js`에서 이미 공개된 함수만 재사용하기 위한 작은 export를 추가할 수 있다. 계산식은 바꾸지 않는다.

## 오류 처리와 한계

- 출생 시각 미상으로 핵심 체계 일부가 빠지면 신뢰도와 해석 범위를 낮춘다.
- 두 개 미만의 핵심 체계가 특정 주제를 지지하면 현실 조건을 세분화하지 않는다.
- 핵심 체계가 상충하면 주 시나리오를 단정하지 않고 양쪽 근거를 함께 표시한다.
- AI가 계산되지 않은 월·회사·도시를 확정하지 않도록 문맥과 시스템 프롬프트 양쪽에서 제한한다.

## 검증

- 신규 테스트는 강함(핵심 3개 이상), 중간(핵심 2개), 약함/상충을 검증한다.
- 보조 체계만으로 핵심 결론을 뒤집지 못하는지 검증한다.
- 시기 교집합이 없는 경우 월 단위 문구를 만들지 않는지 검증한다.
- 기존 `npm run test:unse`와 `npm run build`를 실행한다.
