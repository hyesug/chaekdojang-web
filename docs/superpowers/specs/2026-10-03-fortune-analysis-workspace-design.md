# 운세 분석 워크스페이스 설계

## 목표

`/unse/`를 책도장 "청록 잉크 아카이브"의 일부로 보이게 하면서도, 여러 명반을 읽고 질문을 이어 가는 집중형 분석 도구로 재구성한다. 신비·예언·정확도 과시 대신, 계산된 값과 그 해석의 경계를 드러내고 사용자가 현재 단계와 다음 행동을 이해하도록 한다.

이 작업은 화면 구조, 스타일, 접근성, 상태 문구만 바꾼다. 열다섯 체계의 계산, `engine.js`·`compat.js`·`forecast.js`의 판단, AI 컨텍스트 생성, 프로필 및 질문권 API 계약, 결제·정산 흐름은 바꾸지 않는다.

## 확인한 현재 상태

- 정적 운세 앱은 `public/unse/`의 바닐라 ES 모듈이며, `app.js`는 `src/`를 빌드한 산출물이다.
- 개인/궁합 입력과 계산, 저장 프로필 한 벌의 자동 불러오기, 결과 URL 복원, 15개 체계 계산, AI 스트리밍과 재시도는 이미 있다.
- `/ai-credits`에는 기존 질문권 조회·구매·결제 완료 흐름이 있다. 정적 운세 화면은 현재 잔액을 보여 주지 않고 이 페이지로만 링크한다.
- 질문권 예약은 `app/fortune-ai/route.ts`의 `FORTUNE_AI_REQUIRE_LOGIN` 환경 설정이 켜졌을 때만 수행된다. 화면은 API 응답을 기준으로 로그인·잔액 부족을 표현하고, 환경 설정을 클라이언트에서 추정하지 않는다.
- 현재 결과는 명반 요약, 오늘/이달 탭, 프로필 저장, 긴 종합 보고서 순서이며, 계산값·해석·AI의 차이를 충분히 표기하지 않는다.

## 디자인 원칙

1. 공통 토큰을 사용한다. 배경 `#F3F2EB`, 종이 `#FCFBF7`, 잉크 `#102A2C`, 청록 `#174A46`, 세이지 `#78988F`, 도장 와인 `#8B3040`을 역할별로 쓴다.
2. 흰 카드의 연속과 둥근 대화 버블을 줄인다. 섹션은 얇은 rule, 편집형 제목, 여백, `details`로 구분한다. 기본 반경은 4~6px이며 표·기록에는 그림자를 쓰지 않는다.
3. 결과의 모든 해석은 `해석`으로, 명반·천문·역법 값은 `계산값`으로 표기한다. 점수와 막대는 계산 근거가 있는 곳에서만 유지하고, 객관적 예측 정확도처럼 보이는 문구를 쓰지 않는다.
4. 운세는 상징적 해석임을 설명하며 불안·긴급성·가짜 사회적 증거를 쓰지 않는다.

## 정보 구조와 화면 흐름

### 최초 방문

1. 작은 서비스명, 한 줄 설명, 개인 운세/궁합 분절 탭을 표시한다.
2. 즉시 기본 입력을 시작한다. 이름, 성별, 양력/음력, 생년월일, 출생 시각과 출생지는 한 묶음으로 둔다.
3. `태어난 시간 보정과 거주지`는 필요한 항목을 숨기지 않되, 서머타임·거주지 설명을 보조 영역으로 낮춘다. 시간 미상은 별도 체크로 시간 필드를 명확하게 비활성화한다.
4. 명반 생성 버튼 아래에 브라우저 계산, AI 전송, 프로필 저장의 데이터 처리 차이와 개인정보처리방침 링크를 짧게 표시한다.
5. 계산 중에는 실제 엔진 단계와 일치하는 진행 기록을 `aria-live`로 표시한다. 완료하면 결과 시작점으로 포커스/스크롤을 옮긴다.

### 결과

결과 최상단은 분석 대상과 입력 기준을 요약한 기록 머리말이다. 그 아래 순서는 다음과 같다.

1. `해석 · 핵심 종합` — 반복되는 주제, 중요한 일치·상충 지점만 먼저 보인다.
2. `계산값 · 명반 요약` — 사주 기둥과 핵심 천문 값만 보이며, 나머지는 `명반 자세히 보기`에 둔다.
3. `AI 명반 해석` — 현재 분석 대상, 로그인/질문권 상태, 질문 입력과 답변 기록을 둔다.
4. `세부 계산 보기` — 기존 종합 보고서를 기본 접힘 상태로 두고, 핵심/보조/상징 체계를 읽는 순서를 안내한다. 이미 계산된 문장과 표는 삭제하거나 재계산하지 않는다.

개인 결과의 오늘/이달 정보는 핵심 종합 아래의 얇은 탭으로 남긴다. 궁합 결과도 같은 위계를 쓰되 두 사람 이름과 양쪽 입력 기준을 머리말에 함께 표시한다.

### 재방문 로그인 사용자

현재 한 벌만 지원하는 저장 프로필은 "저장된 내 출생 정보"라는 상태 행으로 표시하고, 자동 채움 사실과 수정 가능 여부를 명확히 한다. 여러 저장 명반 선택 기능은 실제 API가 없으므로 만들지 않는다. 공유 URL 복원은 기존 기능을 유지한다.

### 질문권과 결제

AI 패널은 기존 질문권 조회 API로 잔액을 읽을 수 있을 때만 `남은 질문 n회`를 표시한다. 잔액을 조회하지 못하거나 로그인하지 않은 경우에는 각각 로그인 안내와 상태 불명 안내를 구분한다.

질문 전송이 잔액 부족 응답을 받으면 질문 텍스트를 보존하고, AI 기록 안에 도장 와인색의 조용한 paywall 행을 표시한다. 행에는 현재 잔액(응답/조회로 알 수 있을 때), 질문권 구매 링크, 환불·이용조건 링크만 둔다. 구매는 기존 `/ai-credits`에서 수행하며, 돌아온 뒤 입력 중인 질문을 잃지 않는다. 판매 설정이 준비되지 않은 경우에는 기존 화면의 "판매 준비 중" 상태를 그대로 보인다.

`/ai-credits`는 별도 결제 단계이므로 유지한다. 같은 토큰·버튼·표 스타일로 상품, 질문 수, 가격, 잔액, 유효기간, 결제/환불 안내를 정리한다. countdown·압박 문구·과장된 상품 카드는 쓰지 않는다.

## 컴포넌트와 상태

정적 페이지에서는 프레임워크 컴포넌트 대신 일관된 CSS 역할 클래스와 작은 렌더 함수로 구현한다.

| 상태 | 화면 행동 |
| --- | --- |
| initial | 입력 필드와 데이터 처리 안내, 결과 영역은 숨김 |
| validation error | 첫 오류 필드에 `aria-describedby` 오류문을 연결하고 포커스 이동 |
| calculating | 단계별 진행 기록, 제출 중복 방지, `aria-busy=true` |
| engine error | 계산 실패 원인·재시도 행동·입력 수정 경로 표시 |
| empty | 저장 결과/AI 기록이 없을 때 필요한 다음 행동만 표시 |
| AI answering | 질문과 `명반 해석 작성 중` 기록 행, 전송 잠금, 라이브 상태 |
| AI error / network offline | 이미 받은 답은 보존, 원인과 재시도 표시 |
| credit exhausted | 질문 보존, 구매 링크와 조건 안내 |
| payment pending | 기존 결제 화면에서 결제창 시작 상태와 중복 클릭 방지 |
| payment success | 질문권 지급과 갱신된 잔액 |
| payment failure | 실패/취소 원인, 재시도 가능 여부, 주문 상태 불확실 안내 |

AI 답변은 메신저 말풍선 대신, 질문·답변·상태를 구분선으로 나눈 상담 기록으로 표현한다. 답변 상단에는 항상 `AI 명반 해석`을 표기한다. 빠른 질문은 작은 텍스트 버튼으로 남기되 불필요한 pill 형태를 쓰지 않는다.

## 접근성 및 반응형

- 모든 입력은 보이는 label, 도움말, 오류 ID를 연결한다. textarea에도 label을 제공한다.
- `:focus-visible`은 청록 외곽선으로 일관되게 표시하고 hover만으로 상태를 전달하지 않는다.
- 모드 전환은 선택 상태를 `aria-pressed` 또는 tab 의미론으로 알린다. 상세 `details`는 키보드 기본 동작을 유지한다.
- 계산·AI 스트리밍·결제 상태는 `role=status` 또는 적절한 live region으로 알린다. 오류에는 `role=alert`를 쓴다.
- 360~390px에서는 날짜를 논리적 2열/1열로, AI 입력과 전송은 세로 흐름으로 전환한다. 키보드가 열려도 입력 행이 가려지지 않게 sticky UI를 두지 않는다.
- 768px에서는 입력과 결과의 읽기 폭을 유지하고, 1280px 이상에서도 결과 문서 폭을 과도하게 넓히지 않는다. 표는 의미 있는 경우에만 수평 스크롤을 허용한다.

## 성능과 안전

- 첫 화면은 지금처럼 `boot.js`만 받고, 무거운 엔진·보고서·AI 모듈은 첫 입력 또는 공유 URL 복원 때만 동적 로드한다.
- 디자인 목적의 라이브러리, 웹폰트, 대형 이미지, 장식 애니메이션을 추가하지 않는다.
- `src/`를 고친 뒤 `npm run unse:bundle`로 산출물 `app.js`와 chunk만 갱신한다. 산출물을 직접 편집하지 않는다.
- AI에 보내는 context, 고해상도 질문별 계산, 스트리밍·재시도·질문권 정산 로직은 유지한다.

## 구현 파일 경계

- `public/unse/index.html`: 입력의 구조·의미론·보이는 안내만 바꾼다.
- `public/unse/assets/style.css`: 공통 토큰에 맞춘 분석 워크스페이스 레이아웃, 상태, 반응형 규칙을 담당한다.
- `public/unse/src/boot.js`: 폼 오류 연결, 계산 진행/오류 상태, 모드 접근성을 담당한다.
- `public/unse/src/ui.js`: 개인/궁합 결과의 위계, 계산/해석 라벨, 접힌 세부 보고서, 프로필 상태를 담당한다.
- `public/unse/src/ai.js`: AI 기록 UI, 질문권 상태 표시, 전송·오류·재시도·paywall의 화면 상태를 담당한다.
- 필요한 경우 `public/unse/src/credits.js`: 기존 질문권 조회 API를 읽기 전용으로 감싸며, 결제/정산을 새로 만들지 않는다.
- `app/ai-credits/page.tsx`: 기존 상품·결제 계약을 보존한 채 페이지 시각 시스템과 결제 상태를 정리한다.
- 관련 운세 테스트와 빌드 검증을 추가·실행하되, 계산 회귀 테스트의 기대값은 UI 변경 때문에 수정하지 않는다.

## 검증 기준

개인/궁합의 입력·계산·공유 URL 복원을 모두 확인한다. 로그인/비로그인, 프로필 있음/없음, 질문권 있음/없음, AI 정상/스트리밍 오류, 결제 준비/성공/실패 상태를 실제 가능한 API 응답 또는 안전한 화면 단위 테스트로 검증한다.

`npm run test:unse`, `npx tsc --noEmit`, `npm run build`를 실행한다. 360~390px, 768px, 1280px 이상에서 입력, 결과, 15개 체계 상세, AI 입력, 긴 답변, 결제 화면을 캡처 기준으로 검토한다.
