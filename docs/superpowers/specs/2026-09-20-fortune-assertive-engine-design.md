# 단언형 명반 분석 엔진 설계 (초구체화 2단계)

## 목표

1단계에서 만든 것: 월 단위 계산 → 사건 후보 → 시기 구간.
여기서 한 단계 더 간다.

```
"이 시기에 이직운이 있을 수 있습니다"
→ "이 시기에 직업이 바뀐다. 배우자는 자기 일이 확실한 실무형이다.
   직업이 먼저 움직이고 집이 그 뒤를 따른다."
```

핵심 원칙 한 줄:

> **계산 정밀도는 높이고, 추론은 적극적으로 하되, 근거 없는 디테일은 만들지 않는다.**

단언은 **근거의 강도를 드러내는 표현 방식**이지, 데이터가 없는 자리를 채우는
면허가 아니다. 이 문서의 모든 장치는 그 선을 코드로 강제하기 위한 것이다.

## 3. 근거 없는 디테일을 막는 장치

이 설계에서 가장 중요한 부분이다. **코드가 강제한다.**

### 장치 ①: 근거 없는 항목은 만들어지지 않는다

`profile.js` 의 `item()` 은 `basis` 가 비면 **항목 자체를 반환하지 않는다.**

```js
const item = (axis, value, basis, opts) => {
  const b = (basis ?? []).filter(Boolean);
  if (!b.length || value == null) return null;   // 근거 없으면 항목이 없다
  ...
};
```

그래서 "소유의 방향"처럼 늘 문장이 나오는 항목도, 그 판정을 뒷받침할 자리가
없으면 답에 아예 등장하지 않는다. 프롬프트도 "여기 없는 차원은 답에서도 만들지
말 것"이라고 못박는다.

### 장치 ②: 숫자는 범위로만, 추정 표시를 달고

나이차·터울처럼 숫자가 들어가는 항목은 `estimate: true` 가 붙고, 출력에
"※초구체화 추정 — 명반에서 이 숫자가 직접 나오는 것은 아니다"가 따라붙는다.
테스트가 이를 검사한다.

### 장치 ③: 자녀 수·성별은 아예 만들지 않는다

`childrenProfile` 은 활성도와 터울 경향만 낸다. `caveat` 에 명시하고,
테스트가 출력에 "명/아들/딸"이 섞이지 않는지 본다.

### 장치 ④: 도시 비교는 "실제로 달라지는 것"만

처음에는 도시마다 하우스 내용으로 점수를 매겼다. 그런데 국내는 경도 폭이 3도,
위도 폭이 5도라 하우스가 거의 안 움직인다. **전부 동점이 나왔고, 동점을 정렬하니
목록에 적어 둔 순서가 그대로 1·2·3위가 되었다** — 네 주제가 전부 '서울·성남·수원'
으로 같았다. 순위처럼 보이지만 아무 뜻이 없는 값이다.

그래서 기준 도시와 견주어 **행성이 하우스를 갈아타는 곳**과 **라인이 가까운 곳**만
센다. 달라지는 곳이 없으면 "국내 안에서는 이 명반의 하우스 배치가 사실상 같다"고
말하고 순위를 만들지 않는다.

## 4. 단언 등급 (Tier)

`profile.js` 의 `tierOf(coreSystems, timingTechs)`.

| Tier | 조건 | 어떻게 말하는가 |
|---|---|---|
| **S** | 핵심 체계 3개 이상 + 같은 시기를 짚은 기법 2개 이상 | "이 시기에 직업이 바뀐다." 답 맨 끝에 한 번만 최우선 시나리오임을 밝힌다 |
| **A** | 핵심 2개 이상 + 기법 1개 이상 | "가장 강하게 나타나는 것은 ~이다" |
| **B** | 핵심 1개 이상 | "두 번째 시나리오는 ~이다" |
| **C** | 그 외 | "이 부분은 초구체화 추정이다" |

### 두 번 고친 것

처음에는 **모든 질문이 Tier S** 로 나왔다. 두 군데가 느슨했다.

1. **기법을 "있기만 하면" 셌다.** 세 해를 보는 동안 솔라 아크든 프로펙션이든
   뭔가 하나는 반드시 걸린다. → **가장 강한 구간 그 해**를 함께 짚는 기법만 센다.
2. **구간 전체의 체계 합집합을 썼다.** 넉 달 동안 네 체계가 한 번씩만 끼어도
   '넷이 합의'가 됐다. → **정점 달에서 그 달 무게의 20% 이상**을 낸 체계만 센다.

고친 뒤 실제 분포 (명반 3개 × 질문 3개):

```
S 4개 · A 8개   (핵심 2~3개, 기법 1~4개로 갈림)
```

상충 신호가 있으면 S 로 올리지 않고 한 단계 내린다.

## 5. 답변의 두 층

```
[1층] 사람이 궁금한 것을 먼저 — 체계 이름도 용어도 없이, 일어날 일로
[2층] [계산 근거] [강한 교차 신호] [초구체화 추정] [대안 시나리오]
```

원인 → 사건 → 반응 → 결정 → 후속 결과 순서로 **한 장면으로 이어 쓴다.**
가능성은 **주 시나리오 하나 + 대안 하나**로 끝낸다.

## 6. 두 사람 (`hires/pair.js`)

혼인은 혼자 하는 일이 아니다. **두 사람 모두 같은 해에 켜지는가**가 조건이다.

해마다 양쪽에 대해 다섯 갈래를 센다 — 베딕 다샤(결혼을 여는 행성이 왔는가),
프로펙션(무대가 7하우스인가), 솔라 아크, 자미 유년 부처궁, 사주 세운×일지.

```js
joint = both ? Math.min(a.score, b.score) : 0
```

한쪽이 0이면 곱해서 0이 된다. **그것이 이 모델의 핵심이다.** 겹치는 해가
없으면 "없다"고 말하고 시기를 만들지 않는다.

여기에 합성 차트·데이비슨 차트·D9 비교를 덧붙인다.

## 7. 질문별 계산 (`hires/router.js` 확장)

`자녀` 분야를 추가했고, 확장 추론을 위해 분야를 자동으로 늘린다.

- 결혼을 물으면 `재물` 도 함께 켠다 (상대의 일·돈이 곧바로 따라 나온다)
- 직업 + 통근/이사 낱말 → `이사` 추가
- 결혼 + 집/신혼 → `주거` 추가
- 솔라 아크·프로펙션은 어느 분야에서나 켠다

## 8. 테스트

`tests/unse/hires-ext.test.mjs` — 32개 (전체 103개)

- **규칙** — D7 대응값, 드리슈티 표, 카라카 내림차순, 아루다 10번째 이동 규칙,
  UL2 = UL+1, 경양/타라 = 녹존 ±1, 지겁/지공 = 亥 ± 생시, 삼방사정 = +4/+8/+6,
  유일 = 유월 + 일수, 프로펙션 12년 주기
- **천문 검증** — 솔라 아크가 한 해 약 1도, 아크 = 진행 태양 − 출생 태양,
  루나 리턴 시점의 달이 실제로 출생 황경, 합성 ≠ 데이비슨
- **무근거 금지** — 모든 프로파일 항목에 basis 가 있는가, 숫자 항목에 추정
  표시가 있는가, 자녀 수·성별을 말하지 않는가
- **등급** — Tier 가 실제로 갈리는가 (전부 S 면 실패)
- **두 사람** — 한쪽만 켜진 해를 겹친 해로 세지 않는가
- **지역** — 차이가 없으면 순위를 만들지 않는가, 있으면 무엇이 달라지는지 적는가

## 9. 건드리지 않은 것

- 기존 계산식 전부 (간지·절기·음력·행성·대운·다샤)
- 1단계에서 만든 `hires/` 모듈의 기존 동작
- 기존 화면과 궁합 화면의 기존 구획

`hires/vedic.js` 에 D7 을 더하고 `hires/ziwei.js` 의 `DOMAIN_PALACES` 에
`자녀` 를 더한 것 외에는 1단계 모듈도 그대로다.
