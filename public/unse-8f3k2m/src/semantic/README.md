# 의미축 해석 엔진 v1 — 직업 (`src/semantic/`)

열다섯 체계의 전통 해석을 **현실의 속성**으로 옮기고, 처음 보는 사람의
생년월일시만으로 직업 성향에 답하는 층입니다.

기존 `hires/interpret.js` 는 그대로 둡니다. 이 폴더는 그 위에 얹는
별도 출력 경로이고, 화면과 AI 문맥이 쓰던 길은 건드리지 않았습니다.

```bash
node scripts/analyze-career.mjs --loo          # 체계 × 속성 성능
node scripts/build-dictionary.mjs validation/people.json   # 해석 사전 문서
npm run test:unse                              # 구조 고정 검사 27개
```

---

## 찾는 것

"P01은 카발라가 맞혔다"가 아닙니다. 그건 그 사람에게만 붙는 이름표라
다음 사람에게 넘어가지 않습니다(실측 LOO 0/11).

찾는 것은 **체계마다 어떤 종류의 현실 속성을 반복해서 잘 포착하는가**입니다.
사람별 담당이 아니라 **속성별 강한 체계**라야 새 사람에게 넘어갑니다.

## 실측으로 찾아 고친 것

### ① 평균이 신호를 지웠다

```
체계 하나하나는 사람을 잘 구별한다   사람 사이 코사인 0.22~0.31
그런데 평균을 내면 모두가 같아진다    0.906
축 최댓값 1.00 이 평균에서 0.13~0.29 로 주저앉았다
```

**→ 평균을 버리고 증거 누적(noisy-OR)으로 바꿨다.** 침묵은 반대가 아니라
말하지 않은 것이므로 신호를 깎지 않는다.

### ② 절대값으로 더하면 표의 평균에 수렴한다

열한 체계가 저마다 한 기호씩 내는데, 그 벡터를 그냥 더하면 **표 전체의
평균**이 나온다. 누가 와도 같은 답이다.

**→ 각 기호를 그 표의 평균에서 벗어난 만큼으로 바꿨다.** 탐랑이
'미적감각 0.85'라는 사실보다, 열네 주성 평균이 0.35인데 탐랑만 0.85라는
것이 정보다. 이 평균은 표의 성질이라 사례를 보지 않고 구해진다.

### ③ 수가 많은 쪽이 이겼다

직접 증거를 내는 체계는 넷인데 간접·약한 증거는 열하나다. 열하나가
저마다 조금씩만 말해도 넷을 덮었다 — 개발자에게 '신체'가 1위로 나왔다.

**→ 증거 등급마다 몫을 나누고(`direct 1 · indirect 0.40 · weak 0.18`),
직접 증거가 적으면 보조 몫도 같이 줄인다.** 시각 미상이라 자미·점성이
빠진 두 사람이 가장 나빴던 것(−0.33 · −0.52)이 이 때문이었다.

### ④ 변환층 자체가 틀렸다

정답 속성을 **그대로 넣어도** 정답 업종이 1위로 안 나왔다(6/11). 금융
원형에 `verbal` 이 없어 보험교육이 영업으로, 영업 원형에 `physical` 이
없어 대리점이 요식으로 갔다. 명반과 무관한 버그였다.

**→ 업종 원형을 손으로 쓰지 않고 그 업종에 속한 직업들의 평균으로
만든다.** 업종이란 곧 그 안의 직업들이므로 따로 적을 이유가 없다.

### ⑤ 사주 표에 '대인'이 아예 없었다

열한 명 가운데 넷에서 **대인이 실제로 가장 높은 축인데 사주가 한 번도
그것을 말하지 않는** 일이 되풀이됐다. 한 사람 때문이 아니라 표의 구멍이다 —
명리는 식상을 '표현과 사교', 정재를 '사람을 상대해 꾸준히 버는 자리'로
읽는다. **있는 뜻을 안 적어 두었던 것이라 메웠다.**

### ⑥ 원국이 해마다 바뀌었다

육임은 묻는 순간으로 판을 세우고 태을·구성학은 그 해 연반을 본다.
그대로 두니 같은 사람의 '타고난 결'이 해가 바뀌면 달라졌다.

**→ 원국 해석은 태어난 순간으로 판을 세운다**(`natalFortune`).

## 성적 (11명 · 사람 단위 LOO · 평균을 뺀 자리에서)

```
                        고치기 전    고친 뒤
합친 것                   0.074      0.107
남의 명반                  0.076      0.084
합친 벡터끼리 코사인         0.899      0.526   ← 낮을수록 사람을 구별한다
```

고치기 전에는 **남의 명반과 구별되지 않았습니다.** 지금은 넘습니다.
속성별 보정은 in-sample 0.118 · LOO 0.107 — 그 차이(0.011)가 과적합의
크기이고, LOO 가 보정 없음(0.106)보다 높으므로 **아주 조금이지만 새
사람에게 넘어갑니다.**

사람별로는 연구원 0.69 · 미용실 0.51 · 트레이너 0.25 · 보험교육 0.22 로
읽히고, 병원실장 −0.36 · 인테리어 −0.21 은 아직 반대로 읽습니다.
**둘 다 출생 시각을 모르는 사람입니다.**

## 규칙을 고칠 때

```
한 사람에게만 나타나는 현상        → 수정 금지
서로 다른 2~3명 이상에서 반복
  + 전통적으로도 더 타당한 해석    → 수정 후보
LOO 에서도 나아짐                → v1 에 반영
```

고친 뒤에는 **반드시 `--loo` 를 다시 돌리고 수정 전/후를 둘 다 남깁니다.**
위 ①~⑥ 이 그 기록입니다.

`categories.js` 의 `SHARPNESS`·`MIN_P`, `ensemble.js` 의 `INDIRECT_SHARE`·
`WEAK_SHARE` 는 자유 모수입니다. 사례를 보고 고르지 않았고, 바꾸면 LOO 를
다시 돌립니다.
