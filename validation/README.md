# 검증 사례 모으기 — 아무것도 몰라도 됩니다

이 폴더에 `cases.json` 파일 하나만 만들면 됩니다. 만들고 나서

```bash
npm run unse:validate
```

를 치면 명반이 실제로 맞히는지 숫자로 나옵니다.

`cases.json` 은 `.gitignore` 에 들어 있어 **깃에 올라가지 않습니다.** 다 돌린 뒤 지우셔도 됩니다.

---

## 1. 얼마나 모아야 하나

**사람 여섯~여덟 명, 한 사람당 사건 네다섯 개.** 합쳐서 **30건쯤**입니다.

왜 30이냐면 — 명반이 "상위 35%"를 짚는지 "그냥 우연(50%)"인지 가리려면 그 정도가 필요합니다. 열 건으로는 어느 쪽인지 알 수 없습니다.

사람이 적고 사건이 많은 것보다 **사람이 많은 쪽이 훨씬 낫습니다.** 한 사람의 사건 열 개는 그 사람 명반에만 맞는 것일 수 있지만, 여섯 사람에서 고르게 맞으면 그건 다른 이야기입니다.

## 2. 어떤 사건이 좋은가

**좋은 사건**

- 날짜가 분명한 것 — 연도는 필수, 월까지 알면 훨씬 좋습니다
- 그 사람이 기억하는 것 — "2019년 3월에 이직"
- 아래 여덟 분야 중 하나에 들어가는 것

**피해야 할 사건**

- "그때쯤 힘들었다" 같이 흐린 것
- 본인이 날짜를 지어내야 하는 것
- **제(클로드)가 이미 답을 아는 것** — 지금까지 맞혀본 사건들은 빼세요. 오염됐습니다

## 3. 분야는 이 여덟 개 중에서 고릅니다

| 분야 | 이런 일 |
|---|---|
| `직업` | 이직 · 입사 · 퇴사 · 승진 · 창업 · 부서 이동 |
| `재물` | 목돈 · 큰 지출 · 대출 · 정산 · 투자 손실 |
| `관계` | 연애 시작 · 헤어짐 · 큰 다툼 |
| `결혼` | 상견례 · 예식 · 혼인신고 |
| `주거` | 집 계약 · 매매 · 독립 · 동거 시작 |
| `이사` | 이사 · 타지역 이동 · 해외 |
| `건강` | 수술 · 치료 시작 · 크게 아팠던 때 |
| `자녀` | 임신 · 출산 |

분야 이름은 **표의 왼쪽 글자 그대로** 적어야 합니다.

## 4. 파일 모양

`validation/cases.json` 을 만들고 이렇게 씁니다. `cases.example.json` 을 복사해서 고치면 편합니다.

```json
[
  {
    "id": "가족A",
    "birth": {
      "name": "가족A",
      "gender": "male",
      "year": 1988,
      "month": 7,
      "day": 3,
      "hour": 9,
      "minute": 30,
      "birthPlace": "부산",
      "homePlace": "서울"
    },
    "events": [
      { "domain": "직업", "year": 2015, "month": 4,  "what": "첫 직장 입사" },
      { "domain": "이사", "year": 2015, "month": 6,  "what": "서울로 이사" },
      { "domain": "결혼", "year": 2019, "month": 10, "what": "결혼식" },
      { "domain": "주거", "year": 2021,               "what": "전세 계약" },
      { "domain": "직업", "year": 2023, "month": 11, "what": "이직" }
    ]
  },
  {
    "id": "친구B",
    "birth": { "...": "같은 모양으로" },
    "events": []
  }
]
```

**채우는 요령**

- `id` — 아무 이름이나. `"A"`, `"이모"` 처럼 알아볼 수만 있으면 됩니다
- `gender` — `"male"` 또는 `"female"` (영어로)
- `hour`·`minute` — **모르면 빼세요.** 지어내면 안 됩니다. 시각을 모르면 자미두수 계산을 건너뜁니다
- `birthPlace`·`homePlace` — 시·군 이름. 목록에 없으면 **가장 가까운 시·군**으로 (경도가 가까우면 결과가 거의 같습니다)
- `month` — 모르면 빼도 됩니다. 연도만으로도 채점됩니다
- 쉼표·괄호를 빠뜨리면 파일이 안 읽힙니다. 붙여넣고 고치는 쪽이 안전합니다

## 5. 돌리기

```bash
npm run unse:validate
```

세 단계가 차례로 나옵니다.

1. **눈 가리고 예측** — 출생 정보만 넣습니다. 사건은 보여주지 않으므로 답을 보고 맞출 수 없습니다
2. **채점** — 실제 사건이 예측 목록의 몇 %에 있었는지
3. **무작위 기준선** — 남의 사건과 500번 섞어 같은 방식으로 채점합니다

## 6. 결과 읽는 법

마지막에 **p값** 하나가 나옵니다.

| p값 | 뜻 |
|---|---|
| **0.05 아래** | 섞었을 때보다 확실히 낫습니다. 신호가 있습니다 |
| 0.05 ~ 0.2 | 애매합니다. 사례를 더 모아야 합니다 |
| **0.2 위** | 우연과 구별되지 않습니다 |

**미리 말씀드립니다 — p ≈ 0.5 가 나올 가능성이 가장 높습니다.** 점성술의 예측력은 밖에서 여러 번 제대로 검증됐고 결과는 일관되게 "효과 없음"이었습니다. 그 숫자가 나와도 뭘 잘못한 게 아닙니다.

그래도 재야 하는 이유는 이겁니다. **지금은 출발점조차 모릅니다.** 숫자가 있어야 앞으로 고치는 것이 도움이 되는지 아닌지를 알 수 있습니다. 여태 열한 번 고쳤는데 그게 나아졌는지 나빠졌는지 잴 방법이 없었습니다.

## 7. 그다음

`cases.json` 이 생기면 **고치기 전과 후를 같은 자로 잴 수 있게 됩니다.** 그때부터는

- 고전 시간주 연결이 실제로 도움이 됐는지
- 베딕을 뺀 것이 옳았는지
- 나머지 열한 체계 중 쓸 만한 것이 있는지

전부 의견이 아니라 숫자로 답이 나옵니다.
